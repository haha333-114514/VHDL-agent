# 知电——基于仿真反馈的数字电路学习智能体

版本：0.5 本地原型。赛道：AI 智能体（Agent）开发。

## 一、创作背景

数字电路学习中，编译通过和示例输入正确只是起点。复位与使能同时有效、序列发生重叠、历史样本顺序混淆等问题，往往需要针对性的输入才能暴露。初学者即使拿到正确代码，也可能没有理解原因。

本作品源于实际 VHDL 学习与仿真经验，将“任务规格—测试—反例—解释—练习”组织成可操作的学习过程。教学案例重新编写为11 组固定接口的独立小电路，项目不会读取原课程作业。

## 二、目标与定位

帮助初学者回答三个问题：

1. 我的电路在哪种输入下不符合规格？
2. 实际波形与参考值怎样支持这个判断？
3. 修改后，我能否解释行为并完成变式问题？

本原型的重点是可复查证据与教学反馈，不将模型文字解释直接当作正确性判定。

## 三、功能介绍

### 1. 11 组教学实验

包含五人表决、同步计数器、101 重叠检测、三抽头 FIR，以及新增的有符号加法、generate 加法树、文件驱动 ROM、LUT、RAM、两级流水线、迭代乘法器。每题提供明确规格、接口、已知教学错误、参考实现和固定测试集。

新增 7 题根据用户提供的课件标题推测设计，没有读取对应 PPT 正文。标题映射、检查点和器件验证限制见《课程扩展实验.md》。

### 2. 真实编译与仿真

调用本机 GHDL 分析、展开、仿真。先做基础检查，再按任务补充完整测试。Python 规格模型生成参考结果；测试平台不可由学生编辑器或模型工具修改。

### 3. 证据诊断与可视化

展示通过数、失败数、首个反例、相关代码行、检查点采样、原始日志与 VCD。源码变化时提示重新验证，避免把旧结果套在新代码上。

输出含 X、U、Z 等非二值电平时判为不通过，采样图留空并标记“非 0/1”。每次仿真使用独立日志标记，检查点数、顺序、时间、输入和参考值必须与固定清单一致；提前终止不计为通过。清单可在“验证资料”中查看和下载。

### 4. 分层提示与修复验证

提示分为“观察输入”“联系概念”“修改方向”。本地参考版本明确标注为内置教学实现，在独立目录仿真后由用户选择应用。

模型模式可提出候选代码，只有经过实际完整测试后才显示验证通过。候选代码不自动覆盖编辑器。

### 5. 理解检查与长期记录

22 道理解与变式题由服务端判分。SQLite 分开保存运行结果、参考运行和答题表现；查看历史可以恢复相应源码与证据。练习状态用于复习安排，不推断学生已经掌握。

### 6. 可选模型智能体

接入支持工具调用的 Chat Completions 或 Responses API 模型后，模型可选择读取规格、运行补测、读取采样、读取学习统计和验证候选修改。内置 OpenRouter 免费模型预设，需用户自行申请密钥，额度与可用性以平台为准。执行轨迹显示实际工具调用，最大 6 轮规划和 1 轮仅归纳结果的收尾请求 / 8 次工具调用。没有模型密钥时使用明确标注的本地规则流程；不会自动切换付费模型。

### 7. 反过来验证“测试是否可靠”

模型提交候选代码后，程序才选择两组新种子，补充随机输入与序列；公开测试及两组复核全部通过，才能显示“已验证”。种子与测试平台哈希保存用于复查，不能由模型指定。有限输入已穷举的任务只重排输入顺序，明确区分验证范围。

另构造 15 个受控功能故障，实际比较基础检查、公开完整测试与追加验证：分别检出 1/15、14/15、15/15。一个只迎合公开输入范围的 FIR 特判版本通过公开测试、被追加验证拒绝；11 个正确参考电路全部通过追加验证。这是验证策略的工程实验，不是模型通用正确率或学习提升结论。见《创新实验结果.md》。

## 四、操作指南

1. 安装 Python 3.10+ 和 GHDL，双击根目录 `启动知电.bat`。
2. 在浏览器打开 `http://127.0.0.1:8765`，选择实验并阅读规格。
3. 编辑代码或导入符合当前接口的单个 `.vhd` 文件，点击“检查并诊断”。
4. 在执行轨迹中查看工具返回，在诊断区查看失败条件，使用“下个反例”观察采样差异。
5. 逐层展开提示，修改后重跑。必要时选择“参考修复并验证”，再选择是否应用参考代码。
6. 回答下方变式题，在“学习轨迹”查看记录。
7. 点击“导出实验报告”，获得含源码哈希、失败用例和真实日志的 Markdown 文件。

模型增强：在“模型设置”输入模型根地址、标识与 API Key，然后切换为“模型智能体”。此模式会向所配置接口发送当前源码、问题、仿真摘要，以及模型请求的概念统计。默认本地模式不联网。

## 五、效果演示

推荐场景为同步计数器：

- 初始示例在普通输入下通过基础检查。
- 完整测试加入 reset=en=1 的控制冲突，首个失败位于检查点 13、66 ns：预期 0，实际 4。
- 分层提示引导学生理解 if / elsif 的分支优先级。
- 调整分支顺序后重新运行，可通过当前完整测试集。
- 最后回答“同步复位在两个时钟沿之间拉高，输出是否立即改变”的变式问题。

完整流程见同目录《演示脚本.md》。上述数值属于本项目固定示例，在本机 GHDL 6.0.0 上实际复测；不是模型生成的测试成绩。

## 六、实现特点

v0.5 新增教师带练与自主修复目标：模型可调整行动计划，读取失败版本并再次修改，最多保留 3 个候选。公开完整测试与两组追加验证满足固定完成条件，程序才标记修复已验证。界面可以切换各版波形、日志与验证文件，并在相同输入下对照修复前后的实际输出。

教师带练从当前任务的近期错题和未做变式安排理解检查，等待学生实际选择后再评分、解释和记录。选题接口不返回答案键；练习记录供下次带练使用，不被解释为掌握率。计划与工具阶段保存过程快照，中断后可查看已有证据并重新运行。

九个受控流程实验使用脚本提供模型决策、真实 GHDL 执行；另完成真实免费模型的带练与两轮语法修复联调，来源明确分开。详细元数据、失败记录、截图和局限见《v0.5教师智能体与验证.md》及同名 JSON。

- 将教学建议绑定到具体失败用例、工具日志和源码版本。
- 利用边界补测展示“普通输入正确仍可能有错”。
- 模型通过受限工具取得证据，候选修改在独立目录复测。
- 逐轮记录免费路由实际返回的模型和服务报告用量，未报告费用不当作零。
- 用户可以先看提示再修改；运行结果与理解检查分别保存。
- 无 pip 与前端构建依赖，便于离线展示基础功能。

## 七、当前验证范围与后续方向

固定教学回归包括 11 个错误版本与 11 个参考版本；自动化测试覆盖工具执行、编译 / 运行失败、报告、学习记录、接口边界和模型工具循环。回归结果不代表通用代码修复能力，也没有进行学生学习效果对照实验。

2026-10-20：55 项自动化测试通过；另用真实 GHDL 复核两类曾经误判通过的评分边界，均被修正。一次真实免费云实验通过公开 103/103、两组追加各 247/247 个检查点，三轮响应均报告费用 0。详细对照和可复查元数据见《v0.4验证与改进.md》及同名 JSON。

本机没有模型 API 密钥时，不能宣称真实云模型联调通过。协议与编排可以通过模拟模型传输测试，网络与具体账户能力需要实际配置后核验。

当前仅支持11 组固定接口、单文件 VHDL-2008 电路。没有 PDF 题目自动解析、任意工程自动接入、综合 / 布局布线、硬件板级验证、多人账号或公开执行沙箱。后续可在教师授权题库上扩充任务、独立测试集和学习效果评估。

## 八、提交内容

源码与启动入口、本文档、演示脚本、架构说明、自动化测试、源码打包脚本。执行 `python tools/package.py` 生成提交 ZIP。提交包不包含 API Key、个人学习记录或私有课程资料；评审机需要单独安装 Python 与 GHDL。
