# 架构与验证

## 系统结构

```text
浏览器：源码 / 规格 / 反例 / 采样图 / 练习
  │ 本机 HTTP + 来源校验 + 会话请求令牌
Python 标准库服务
  ├─ 固定教学工作流：基础检查 → 完整测试 → 证据诊断
  ├─ 可选模型循环：Chat Completions / Responses API → 受限函数 → 结果回传
  ├─ GHDL 运行器：固定参数、独立目录、进程与输出上限
  ├─ 固定规格：Python 参考值 → 独立 VHDL 测试平台
  └─ 本地数据：SQLite + 源码 / 日志 / VCD / 报告
```

## 模型工具循环

基线仿真由程序先行完成，保证即使模型中断也有实际证据。模型收到固定规格、学生源码、问题、仿真摘要、本地候选诊断和不带答案的当前题库后，可以调用八个函数。

v0.5 用 mission.py 保存固定目标、计划修订、工具取证次数与停止原因。老师带练安排理解题并等待实际作答；自主修复由程序检查原始完整测试或候选公开与两组追加验证，不能由模型文字或计划自报完成。初始计划是默认建议，模型可用 update_plan 调整，未调用的工具不伪装成已执行。

候选版本最多 3 个，均保留源码、结果和独立产物；inspect_attempt、read_waveform、run_simulation 可指定 baseline、latest 或已有 patch 编号。重复源码拒绝再次运行，后续坏版本不替换已经验证的候选。compare_checks 只对齐编号、时间、输入、类型、参考值相同的检查点，提供修复前后与新增不一致的对照，不构成因果证明。

read_learning_memory 限当前任务最近 6 次作答和 3 次运行，不读取旧源码。recommend_practice 仅从当前任务固定题库选题，不返回答案键。浏览器实际提交后，服务核对推荐题与 run_id、记录评分反馈并更新快照和报告。后续选择依据最新记录，不把回答正确当作掌握证明。

阶段与工具返回后原子写入过程快照；缺少当前进程内任务的 running 快照在读取时标记为中断，避免浏览器无限等待。已有证据可查，任务需要重新运行，尚不支持自动从断点续跑。该原型仍按一个服务实例使用一个数据目录设计。

调用由模型响应中的工具请求驱动。Responses API 使用 `function_call` / `function_call_output`；Chat Completions 使用 `tool_calls` / `role=tool`，适配器统一交给相同的受限工具循环处理，并保留供应商所需的推理签名供后续请求使用，不向界面展示。程序验证函数名与参数，执行工具并回传结果。最多 6 轮规划和 1 轮仅归纳结果的收尾请求，共不超过 7 次请求、8 次工具调用；收尾请求不提供工具，若模型仍请求工具，程序拒绝执行。`propose_patch` 仅在新目录验证候选代码，不能覆盖学生源文件、规格或测试平台。

默认提供 OpenRouter `openrouter/free` 免费模型预设；限额和模型供应由平台控制。遇到限流不自动请求付费模型或自动重试。项目未配置密钥时不能声称免费云模型联调通过。

`propose_patch` 在公开测试通过后，才由程序生成两组新种子执行追加验证。工具同时返回公开结果、追加结果与综合 `verified`；只通过公开测试的候选不能被标为已验证。对已穷举有限输入的任务，仅重排输入顺序。每组保存种子、测试平台与受控输入文件哈希、真实日志和 VCD，便于重放；哈希是版本指纹，不是外部认证或形式化证明。

`tools/evaluate_innovations.py` 向正确实现注入有限的受控功能故障，并用真实 GHDL 比较三类测试的检出能力。编译或运行中断单独归为无效，不把编译失败算作功能故障检出；同时复核 11 个正确参考实现，避免只看检出率而忽略误报。

本地模式的提示和参考实现是规则 / 教学内容，不是模型生成；模型模式的解释由实际配置的模型服务生成。二者在界面与报告中明确标记。

## 独立判定与证据

候选代码与测试平台分文件编译。参考值使用 Python 中的明确规格生成：表决统计 1 的个数、计数器按优先级更新、序列判断后缀、FIR 使用直接卷积。

测试平台每次记录时间、检查点类型、输入、实际值和参考值，最后记录总数与失败数。v0.4 先检查 std_logic 输出是否为字面二值；X、U、Z 或弱电平不参与数字转换，也不能通过预期为 0 的检查。API 使用 actual=null、valid=false 表达，界面显示“非 0/1”，采样连线在该处断开。

Python 独立生成固定检查清单 checks.json。每次接受源码后生成随机日志标记，只解析带本次标记的检查、非二值标记与唯一完成记录。检查数必须非零且与清单相符，顺序、编号、采样时间、输入标签和参考值逐项一致；完成计数与实际检查数和失败数必须一致。只有 GHDL 正常退出、未触发 stop-time / stop-delta 且证据完整，才判为完整执行；零失败才标记通过。这是受控评分协议，不是对任意恶意 VHDL 的安全证明。

首个失败检查点用于生成候选原因，相关行使用静态线索，不能当作唯一根因证明。对自定义修改，规则提示可能不适用，此时应结合原始日志与实际输出判断。

界面的阶梯图展示离散采样，不能用来估计采样间的毛刺。VCD 保留实际事件轨迹。

## 记录与复现

每次实验使用随机 UUID 独立目录，保存被测源码、测试平台、GHDL 产物、原始日志、运行快照和 Markdown 报告。报告带源码 SHA-256，防止混淆不同版本。

相同随机种子重建相同输入序列；新运行的日志标记不同，测试平台字节和 SHA-256 随之改变。原样复查需使用当次保存的源码、测试平台、输入文件、checks.json 和日志，不能仅凭相同种子期待同一个测试平台哈希。

模型最后一轮回复作为教学解释，中间规划文字不拼接为最终结论。已成功返回的每轮响应分别保留请求模型、服务报告实际模型、响应编号、延迟和用量；缺失或无效费用值为未知，只有各轮均报告时才计算完整合计。费用单位由服务商定义，不表示账户总费用；模型中断时已有仿真证据保留，不能把中断当成一次完整联调。

GHDL 报标准库时间不一致时，诊断引导检查系统时间与工具安装，并暂缓模型请求。HTTPS 证书异常也单独提示检查时间和服务证书。Windows 服务独占监听端口，端口被占用时提示换端口，避免不同本地应用共用同一个地址。

SQLite 保存运行索引与练习记录。参考实现运行单独标记，不计入非参考通过次数。非参考运行并不能证明独立原创。答题正确统计是作答次数，重复答题会重复计数，不解释为知识掌握比例。

模型密钥不返回浏览器、不写入运行快照；网页输入仅保留在进程内存。.env 由用户自行配置，源码打包脚本排除该文件及 data 目录。

## 工程测试

执行 `python -m unittest discover -s tests -v`，覆盖：

- 个个教学错误可被完整测试检出，个个参考实现通过。
- 基础测试可漏掉特意设计的边界错误。
- 编译错误、运行错误和缺失工具不伪装为通过。
- 模型函数调用结果正确回传、无效参数处理与轮次上限。
- 模型配置不向客户端暴露密钥。
- 本机请求来源、CSRF、静态资源与产物路径边界。
- 实验创建、提示读取、VCD / 报告导出、记录保存与历史恢复。
- 参考运行和答题记录分开统计。

`tools/evaluate.py` 另生成固定教学集的可复现工程结果，不测试模型泛化或真实学生学习提升。真实模型接口需配置凭据后另行联调。

## 当前限制

这是个人本地原型，不具备面向陌生用户运行任意代码所需的操作系统隔离。服务只监听回环地址；VHDL 静态限制、独立目录和超时并不构成强安全沙箱。

GHDL 仿真结果不等于形式化证明、器件可综合性、时序收敛或硬件实测。若扩展到公开平台、多文件工程或真实板卡，需要分别设计执行隔离、任务解析、独立验证与设备反馈。
